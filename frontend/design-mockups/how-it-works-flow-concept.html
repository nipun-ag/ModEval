How It Works — pipeline flow shape

Rough layout for review before interactive build. Shape mirrors real build_response() control flow: one true parallel fan-out (8 models), then a single converge path. Platform policy and alignment fallback are details inside nodes — not extra visual forks.

Interaction preview (not implemented here): click a node → right-side detail drawer (keeps diagram visible; fits equation / schema / tables). Dashed amber connector = keyword fallback path (shown for IA only).

Genuine forks (worth drawing)

  1. 8-model parallel inference — only real fan-out in run_models(). Converges into one result list before alignment.

One cluster, not eight separate chapter nodes

Not drawn as forks (recommendation)

  • Per-platform policy — input parameter into Context/Align; use platform tabs inside detail, not 5 branches.
  • AI vs keyword alignment — failover, not parallel. Dashed secondary path in Align detail.
  • Disabled/error filtering — note in Normalize/Align detail; don’t split the diagram.

Recommended click pattern

Right-side detail drawer (slide-over panel).

  • Keeps flow orientation visible while reading dense content
  • Scrollable home for schema blocks, equations, tables, quotes
  • Better than modal (traps focus, hides map) or inline expand (blows vertical rhythm of the diagram)

Ambient motion (later build)

  • Slow pulse along connectors only (opacity / dash-offset)
  • No bounce; respect prefers-reduced-motion
  • Selected node: quiet border lift, not a spotlight takeover
